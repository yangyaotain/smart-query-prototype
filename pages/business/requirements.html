1.1

整体架构

以自然语言作为统一入口，在业务口径和权限范围内连接企业数据、智能分析能力与多种成果交付方式。

智能问数总体架构与核心数据流程 按照应用交付、智能分析、数据治理和基础资源四层阅读
01应用交付层面向业务场景
统一使用入口
自然语言问数像与分析师交流一样提出业务问题
可视化分析按需生成摘要、指标、明细和图表
报告与文件形成HTML内容或Word、PDF、Excel成果
业务技能复用沉淀常用分析方法、提示词和业务模板
02智能分析层理解问题并组织任务
完成可信分析
提出业务问题选择主题、技能或上传附件
理解分析意图识别指标、维度、时间和目标
匹配业务口径结合指标、模型关系和业务知识
校验权限范围控制主题、字段和数据范围
查询与计算通过受控通道访问真实数据
生成分析结果组织结论、图表、明细或报告
03数据治理层统一数据语义
保障安全可信
数据接入与模型连接业务数据，维护表、字段和数据关系

知识与分析经验沉淀行业知识、问题样例和分析方法
身份与数据权限控制主题、字段和可访问的数据范围
04基础资源层连接企业现有资源
支撑稳定运行
企业业务数据经营、销售、生产、供应链等数据源
业务知识资源指标、规则、术语和问题样例
智能模型服务语言理解、任务推理和向量检索能力
文件与运行存储附件、模板、任务、报告和其他产物
口径统一回答基于已配置的指标、模型和业务知识。

整体逻辑：业务入口 → 智能理解与受控查询 → 多形式结果交付；数据、口径、知识和权限共同支撑全过程。

1.2

业务架构

从多类业务入口出发，经AI意图判断进入文档或HTML输出，并通过看板、报告、引用和版本机制形成完整闭环。

智能问数业务端整体业务流程 按照业务发生顺序自上而下阅读
01业务入口
通用问数自由提问、连续追问、趋势、归因、对比和数据解读
附件与图片上传数据文件、业务附件或图片并结合内容分析
上传模板提供文档模板并按指定结构生成成果
选择技能按照后台配置的技能提示、数据查询和模板执行
引用或定时引用看板、报告，或按计划自动发起任务
02AI理解、数据查询与任务编排

结合用户要求、附件内容、技能配置和引用上下文，识别本次任务是分析、生成文件、修改看板还是修改或写入报告。

意图理解上下文组织指标与数据查询权限校验输出方式判断
判断成果载体与处理方式 明确文件、技能或模板要求进入文档输出；通用分析默认进入HTML输出；引用修改进入对应成果版本流程。
文档输出
适用：明确要求Word/PDF/Excel、上传文档模板、执行文档型技能，或附件/图片分析后要求生成文档。
生成文件成果按照内容要求或模板生成Word、PDF或Excel，并展示生成状态。
预览、下载或保存报告未保存的文件可以直接下载；需要持续管理的成果保存到“我的报告”。
AI对话修改报告再次引用报告，要求改写、补充或向指定章节写入当前分析内容。
确认后形成新版本AI先生成修改候选，用户确认保存后形成新的报告版本，并可重新导出。
Word / PDF / Excel保存我的报告AI修改或追加版本与再次导出
HTML交互结果
适用：通用问数、引用分析以及未明确要求文件的附件、图片和数据分析。
大模型自动组织展示根据结果内容选择文字说明、指标卡、表格、图表、图片或组合布局。
继续基于上下文分析支持自由追问、趋势分析、归因分析、对比分析和数据解读。
保存与二次制作完整HTML结果整体保存为看板；表格、图表和指标卡可保存到“我的仪表盘”，再手动编排看板。
导出结果HTML分析可导出Word和PDF；表格可以单独导出Excel或数据文件。
整体保存看板局部保存仪表盘手动编排看板导出Word/PDF/数据
03引用分析、成果修改与版本管理
引用后仅进行分析

引用“我的看板”或“我的报告”作为上下文，生成HTML分析结果并支持继续追问。

不修改原成果，不产生新版本
引用后要求修改或写入

AI生成看板草稿、报告修改候选或追加内容，用户确认保存后写入目标成果。

确认保存后形成新的看板或报告版本
修改边界：AI生成的HTML看板可以通过对话继续调整；人工组件编排的看板可以引用分析，但组件增删和布局调整仍进入看板编辑页完成。PDF等交付文件通过修改报告内容源后重新生成。
继续对话并重新进入任务判断 任何分析结果、看板或报告都可以再次作为上下文，继续追问、调整输出方式或生成新的成果版本。

完整业务闭环：多类业务入口 → AI任务编排 → 文档或HTML输出 → 看板与报告沉淀 → 引用分析或修改 → 新版本与继续追问

历史与当前输入

Java 保存 Thread 标识，Python 恢复推理历史；每轮显式提供 job-context 与 current-turn-attachments，避免误用历史任务和附件。

流式过程与业务记录

Python 发出原生事件并发送 SSE 心跳；Java 将事件投影为前端时间线，普通问数的消息与任务写入业务库。

去重与停止

clientRequestId 处理重复提交。取消沿 Java → Python → Codex Turn 传递，是执行期间可发生的旁路。

执行上限

普通问数默认 10 条；Java 当前 SQL 校验上限为 100 条、60 秒。报告按数据集形态设限，复用同一安全网关。

结构化展示按需生成

execute-query 返回数据和 executionId；render-query-result 引用真实执行结果，验证图表字段并写入 QUERY_RESULT。普通回答不展示 SQL。

代码与提示词边界

语义路由、澄清和一次修复由 Skill 指导 Agent 执行；Java 执行 SQL 校验。REPORT_DATA 批量取数另见报告流程。

源码 / 约定：query-data/SKILL.md · smart_query_api.py · AgentToolService · SqlSafetyService

网页编辑的采纳点

AI 返回候选正文，用户采纳后再保存。报告助手的临时 Thread 与授权信息默认在 Redis 保留 2 小时，正文以 MySQL 为准。

模板报告交付条件

统一模板报告保留必需业务组件；NO_DATA 在数据槽位写“暂缺”。必需数据缺字段、无权限、查询失败或超时会阻止交付。

文件目录职责

input/ 为输入附件，work/ 为脚本和数据，qa/ 为视觉质检，output/ 为最终交付。Java 结合文件事件和收尾扫描登记产物。

源码 / 约定：ReportService · report-editing · template-report-generation · REPORT_DATA · AgentSessionArtifactService
