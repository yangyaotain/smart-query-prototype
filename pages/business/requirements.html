Executive Summary

结论总览

整体逻辑可行，但正式系统不能把“页面 HTML”当作唯一资产和跨模块数据协议。

01

普通问数生成交互结果

文字、表格、图表、指标卡和图片通过平台组件生成；特殊需求才进入受控自定义 HTML。

02

明确文件要求生成文件成果

Word、PDF、Excel、PPT 进入异步文件任务，在会话中返回摘要、进度和文件卡片。

03

表格与图表沉淀为资产

保存 WidgetAsset，而不是复制浏览器 DOM；多个资产通过 BoardWidget 编排为看板。

04

实时来自数据快照

HTML 结构保持稳定，后台生成新快照，前端收到通知后拉取数据并重新渲染。

05

报告插图采用图片节点

图片节点保留 assetId、snapshotId、imageId 和版式参数，更新时可以原位替换。

06

AI 编辑结构化报告源

AI 返回受控节点操作和差异候选；Word、PDF、PPT 是可重新生成的输出版本。

可行
推荐采用“交互结果资产 + 文件成果资产”双资产体系

HTML 是可控的展示载体；查询定义、数据快照、展示配置、布局覆盖和文档内容分别保存、分别版本化。

两级渲染能力

平台标准组件优先，自定义 HTML 仅作为特殊展示能力。

1
标准内容块text / table / chart / kpi / image / file
2
ViewSpec组件类型、字段映射、图例、颜色、格式化和交互
3
Custom HTML BundleHTML、CSS、数据协议和渲染器版本不可变打包
4
安全沙箱隔离 DOM、禁止任意网络和凭证读取、资源白名单

自定义 HTML 的运行边界

隔离运行sandbox iframe 或隔离 Web Component，不继承主系统全局对象。
平台注入数据禁止任意 fetch / XHR / WebSocket，数据通过安全消息接口注入。
批准的 SDK只能使用受控图表与交互 SDK，并上报 renderReady。
统一导出视口支持容器尺寸变化、主题切换、数据更新和服务端截图。
Persistence Contract

数据、样式与跨模块传递

把“数据、展示、布局、文档”分开版本化，才能同时满足实时刷新、历史重放、编辑和多格式导出。

查询定义层指标、维度、筛选、时间范围、排序、权限与数据源可编辑
数据快照层字段结构、确定数据版本、数据时间、摘要与对象存储地址不可变
展示定义层ViewSpec 或 HTML Bundle，以及对应渲染器版本独立版本
局部覆盖层看板标题、图例、颜色、宽高、布局与报告图片版式页面私有
渲染缓存层HTML、PNG、PDF 等预览或导出衍生物可重建

跨模块主契约

模块之间传递标识和版本，而不是传递不可控的完整页面。

assetId + assetVersion + snapshotId
  • assetId：定位业务资产。
  • assetVersion：定位展示与查询定义版本。
  • snapshotId：定位确定的数据版本。
  • HTML、PNG、DOCX、PDF 均为可重新生成的渲染结果。

Export Strategy

Word、PDF、Excel 与 PPT 导出

不同目标格式使用不同生成策略。导出任务开始时冻结结果版本和数据快照，生成后返回短期签名下载地址。

统一导出任务

冻结输入固定 assetVersion、snapshotId 与 ReportVersion。
重新校验导出时再次校验用户、组织、行列权限和脱敏策略。
异步执行queued / running / success / failed，支持超时、取消和重试。
安全下载对象存储使用短期签名地址，不在 HTML 中持久化长期 URL。
Implementation Roadmap

推荐实施顺序

先建设结构化结果、数据快照和统一导出，再逐步开放自定义 HTML，避免一开始放大安全与兼容复杂度。

六阶段建设路线
01统一结果协议

ResultArtifact、标准内容块、查询定义、数据快照与基础导出。

02资产化

WidgetAsset、我的仪表盘目录、来源血缘和资产版本管理。

03看板编排

BoardWidget、拖拽布局、局部覆盖、乐观锁和批次刷新。

04报告体系

ReportDocument、图片节点、原位替换、版本发布和 Word/PDF。

05AI会话编辑

节点操作协议、候选差异、数字校验、审计和版本回退。

06受控扩展

自定义 HTML 沙箱、服务端渲染和图片型 PPT 生产管线。

实施优先级

结构化结果与数据快照是地基；任意 HTML 只能在标准链路稳定后作为受控扩展能力开放。

Final Recommendation

最终结论

形成完整闭环：对话生成 → 丰富展示 → 资产沉淀 → 看板编排 → 报告复用 → 文件交付

正式方案应定义为：普通问数生成交互结果资产；明确文件要求生成文件成果资产；表格、图表和指标卡保存为可实时刷新的 WidgetAsset；多个资产在看板中编排；报告插入按快照渲染的仪表盘图片，并通过来源引用实现原位更新；AI 编辑结构化报告源，各类文件作为可重新生成的交付版本。

不建议的实现方式
  • 只保存完整 HTML 字符串并跨模块复制。
  • 从页面 DOM 反向抓取数据生成 Excel。
  • 报告图片只保存临时 URL，不保存来源资产。
  • AI 直接返回整篇 HTML 覆盖正式报告。
  • 实时刷新失败时覆盖上一成功数据。
